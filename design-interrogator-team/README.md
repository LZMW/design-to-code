# Design Interrogator (设计审问官) Team

> 一个专为「研读源码 → 拷问设计 → 产出文档」全流程打造的专家团队。

## 团队简介

Design Interrogator 是一个三专家流水线团队，帮你完成从分析参考项目源码到产出新项目开发文档的完整闭环。

**核心能力**：
- 深度分析现有项目源码，提取架构、模式和技术决策
- 对新的设计方案进行无死角拷问式访谈，解决每个决策分支
- 将所有分析和决策整合为完整、可执行的开发文档

## 团队成员

| 角色 | Agent ID | 职责 |
|------|----------|------|
| 🔀 协调器 | `design-interrogator-coordinator` | 需求解析、阶段编排、产出验证 |
| 📖 代码分析师 | `design-interrogator-analyst` | 深度研读参考源码，提取架构模式和设计决策 |
| 🔍 设计审问官 | `design-interrogator-interrogator` | 从零构建决策树，逐分支拷问直至共识 |
| 📝 文档撰写师 | `design-interrogator-writer` | 整合所有产出，撰写完整开发文档 + ADR + 决策树 |

## 工作流程

```
Phase 1: 代码分析          Phase 2: 设计拷问          Phase 3: 文档撰写
┌─────────────────┐     ┌─────────────────────┐     ┌─────────────────┐
│ 分析参考项目源码  │────▶│ 从零构建决策树       │────▶│ 完整开发文档     │
│ 提取架构/模式    │     │ 逐分支拷问+建议答案   │     │ ADR + 决策树    │
│ 技术栈/设计决策  │     │ 压力测试+边界探索     │     │ 模块接口+部署   │
└─────────────────┘     └─────────────────────┘     └─────────────────┘
```

## 使用方式

### 全流程模式

```
分析 G:\参考项目 的源码，然后拷问我新项目的设计，最后产出开发文档
```

### 仅拷问模式

```
拷问我关于 [新项目] 的设计方案
```

或简单说：

```
拷问我
```

### 从中间阶段启动

```
基于已有的分析报告，开始拷问我的设计
```

```
把分析报告和拷问结果整理成开发文档
```

## 触发条件

协调器会在以下情况自动激活：
- 用户提到"分析源码"、"拷问我"、"压力测试"、"开发文档"
- 用户需要从参考项目到新项目文档的完整流程
- 用户希望对设计方案进行系统性审问

## MCP 工具

团队使用 Context7 查询框架/库的官方文档。三个专家均配置了 Context7 权限，但需要协调器在触发时明确授权才会使用。
